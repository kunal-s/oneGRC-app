# The note generator

Generated by Prototype to Product Kit v2.1 · 2026-08-27

This folder builds the Obsidian note layer over the plan. It starts with a dot,
so Obsidian hides it from the vault and it never appears in the graph.

## What it produces

| Output | From |
|---|---|
| `docs/plan/modules/M-NN.md`, 18 notes | `modules.psv`, plus the screen tables read out of `screen-inventory.md` |
| `docs/plan/slices/SLICE-NN.md`, 53 notes | `slices.psv` |
| `docs/plan/traceability.md` | all three data files, plus `screen-inventory.md` and `decisions.md` |

## Running it

```bash
bash docs/plan/.generator/gen.sh   .
bash docs/plan/.generator/trace.sh .
```

Both take the repository root as their one argument. Each takes a few minutes on
Windows, because the shell forks a subprocess per link.

## Keeping it true

The data files mirror the plan. When a slice changes in `slice-plan.md`, change
the matching row in `slices.psv` and regenerate; when a module's dependencies
change, change `modules.psv`; when an entity is added to `data-model.md`, add it
to `entities.psv`. The plan is the source of record and these files are its
index, so a disagreement between them is always the data file being wrong.

Row shapes, both pipe separated, and the field count is checked:

- `entities.psv` : `id | name | module`
- `modules.psv` : `id | name | purpose | workflow file | depends on | independent of | slices | engines | decisions | decisions needed | enhancements`
- `slices.psv` : `num | title | modules | screens | entities | depends on | proves | status | decisions | decisions needed | enhancements | reads` , twelve fields, always

Check the field count before regenerating, because a short row silently shifts
every column after it:

```bash
awk -F'|' 'NF!=12 {print "bad row " NR}' docs/plan/.generator/slices.psv
```

## The two traps

**A wikilink alias pipe splits a markdown table cell.** Every link that lands in
a table is escaped to `\|` by `esc()`. On this platform `sed` will not emit a
literal backslash from its replacement, so `esc()` uses `perl` and `chr(92)`.
`checkpipes.pl` reports any that got through:

```bash
perl docs/plan/.generator/checkpipes.pl docs/plan/*.md docs/plan/workflows/*.md docs/decisions.md
```

**Never hand-edit a generated note.** The next run discards it. Edit the plan
document, update the data file, regenerate.
