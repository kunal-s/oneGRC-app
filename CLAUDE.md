## What this is

A unified governance, risk, compliance and audit platform for regulated
enterprises, being taken from an approved frontend prototype to a full-stack
product, screen by screen.

- **The prototype** is `github.com/kunal-s/onegrc-project-space`, served at
  `https://onegrc.joulestowatts.online/`. It is **frozen and never edited.**
- **This repository** is the build, served at `http://localhost:5173/`.
  `apps/web` began as a byte-for-byte copy of the prototype.
- **Verification is done in a browser, by clicking.** Never on the strength of a
  passing typecheck. The prototype is the reference for how a screen looks. The
  FRD's functional flow and its acceptance criteria at §20 are the reference for
  what it does. D-042.

## The rules that are not negotiable

1. **Derive, never store.** No `overdue`, no `ageDays`, no `evidenceCount`, no
   `band`, no `stage`, no `tier`, no `netLoss`, and no `department` outside
   `Person`. The complete ruling is section 2 of `docs/plan/data-model.md`. A
   stored copy of a derivable fact is a future lie.
2. **Never invent data.** An honest empty screen is correct. A populated
   invented one is a defect. This project has twice shipped figures that looked
   right and were constants. Trace every number you display back to the record
   it came from.
3. **Every record carries an origin**, one of `reference`, `sample` or `earned`.
   Nothing real may depend on `sample`.
4. **Authorisation is enforced server side**, through `GovernedMutationService`
   and one authority table. Hiding a button is not enforcement. Hide it **and**
   refuse the call.
5. **One engine per concern.** One ladder, one remediation register, one loss
   book, one evidence vault, one audit log, one proof-chain renderer, one clock
   service, one work item. Section 8 of `docs/plan/platform.md` lists all
   fifteen. Never grow a second.
6. **Every change is transactional with its audit entry.** A change that cannot
   be logged must not commit.
7. **Nothing is tracked without a person.** Classification and enrichment
   propose; a human disposes.
8. **Verbatim means verbatim.** Never paraphrase a source extract into a field
   called verbatim.
9. **The FRD wins on what the product does. The prototype wins on how it looks.**
   D-042. The FRD rules the flow, the states, the rules, the permissions, the
   calculations, the sequencing, the fields a screen carries and the acceptance
   criteria at FRD §20. The prototype is guidance, not specification. A
   functional difference from the prototype that matches the FRD is the build
   target, not drift. A visual difference from the prototype is drift and goes
   back, unless it is the minimum consequence of a functional requirement, in
   which case it is a delta and it is recorded in `docs/decisions.md`. The FRD
   rules how the product behaves; it never rules what is in scope. Scope is
   `docs/plan/slice-plan.md` and the customer's.
10. **Report, do not resolve.** Anything ambiguous, contradictory or missing
    becomes a decision needed in `docs/decisions.md`, never a guess. A wrong
    guess that compiles looks exactly like success.
11. **Never build an enhancement recommendation without approval.** Register 3
    of `docs/decisions.md` stays unbuilt until each line is decided.
12. **Every slice ends in something a non-developer can verify by clicking**,
    including at least one step that must FAIL, with the refusal message stated.
13. **Plan documents are edited in place.** Never append, never add a second
    version section, never leave superseded text behind.
14. **Design comes from the prototype.** Reuse `PageHeader`, `SeverityBadge`,
    `StatusChip`, `Button` and `card-surface`. Port the sections the customer
    names and nothing else. Where our data does not exist yet, say so in the
    section rather than rendering a plausible placeholder.

## Hard rules on language

These apply to code comments, commit messages, screen copy and every generated
document. Text that breaks them gets rewritten.

**No em dashes.** Use a colon, a comma, brackets or a full stop. In a table cell
meaning "does not apply", write `n/a`, never a dash.

**No AI-tell vocabulary.** Banned outright: delve · seamless · robust · leverage
as a verb · elevate · unlock · harness · navigate figuratively · landscape ·
realm · tapestry · journey unless the customer's own word · game changer ·
cutting edge · best in class · testament to · at the end of the day · in today's
fast paced world · let's dive in · it is worth noting that. Banned as filler,
allowed only carrying real weight: comprehensive · crucial · vital · essential ·
powerful · significant · streamline · optimise · ensure. Banned constructions:
"It's not just X, it's Y" and every variant; rhetorical triads; "Whether you're
X or Y"; opening a paragraph with Importantly, Notably or Crucially; closing a
section with a summary sentence that adds nothing.

**Plain declarative sentences.** Say the thing. A build document is read by
someone deciding what to do next.

**No hype about the product.** Describe what it does.

```
grep -rn $'\xe2\x80\x94' docs/plan/ docs/slices/ docs/decisions.md CLAUDE.md \
  apps/api/src apps/api/prisma apps/api/scripts packages/*/src \
  apps/web/src/api apps/web/src/pages/live apps/web/scripts package.json
```

The last one must return nothing. It matches the em dash by its bytes, so the
command does not contain one and cannot match itself.

Its paths are the plan this build generates and the code this build wrote, which
is what the language rules govern. Three things are deliberately outside it.
`docs/functional-spec.md` is the customer's document and is not ours to rewrite.
`docs/build-plan.md`, `docs/design/`, `docs/rules/` and `REVIEW.md` pre-date the
kit. Everything else under `apps/web/src` is the prototype as the client approved
it, and rule 9 governs it: an em dash there is removed inside the slice that
rewrites that file, never by a sweep.

Until 2026-08-30 this command read `apps/src`, which is not a path in this
repository, so it silently checked no code at all. Fifty seven em dashes had
accumulated in build-written code behind it. Each is cleared inside the slice
that touches its file.

Until 2026-08-31 the widened command still missed `apps/api/prisma`,
`apps/api/scripts`, `apps/web/scripts` and the root `package.json`, the same
class of hole. Those paths held twenty seven em dashes. Twenty one, in the
files the scaffold slice touches, are cleared there. The other six, in
`apps/api/scripts/register-fixtures.ts` and `apps/web/scripts/check-access-control.tsx`,
are cleared inside the slice that touches each file.
